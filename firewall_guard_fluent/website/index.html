How a block works

Select the rows.

Services, programs, and remote addresses can share one batch. The console groups them before anything is sent.

The machine, in three pages.

Memory, GPU, and disk each have a page. Used, available, and free. Then the applications holding that resource.

Memory.

Working set, standby Windows can reclaim, and memory that is actually free.

GPU.

Engine use and dedicated memory. NVIDIA totals when the driver is there. Windows counters for each app.

Disk.

Free space on each volume, then the processes reading and writing. Ending one closes the app. It does not delete files.

Traffic, with a name beside it.

Live firewall events sit next to current sockets. A remote name comes from the Windows DNS cache. The console does not look inside TLS.

A pattern such as *microsoft.com* resolves to addresses, and those addresses become block rules.

Dry-run first.

The default records what you meant to block. Windows Firewall stays as it is until you turn live mode on and approve the prompt.

Get the highlights.

Processes and services.

Status, start mode, path, and a detail drawer with signer and command line when Windows can provide them.

One table language.

Sort any column. Filter each column. Open a row for the details. The same behavior on every page.

Only your rules.

Removal is limited to the FGF- group this console created. Other products keep their own blocks.

Local, on purpose.

The API listens on 127.0.0.1. It does not decrypt traffic or prove what left the machine.
