Every page earns its place.

Protection. Network. Performance.

The same details view throughout. Sort a column. Filter it. Open the row.

Know the process before you block it.

Services show status, start mode, logon account, and the host command. Processes show CPU, memory, and disk rate. Open one for the signer, version, command line, and parent, when Windows can supply them.

Sockets, then a decision.

TCP and UDP, IPv4 and IPv6, with the owning process. Select the remote endpoints. One batch blocks the distinct addresses. The list is a snapshot. Windows can hide some PIDs.

A pattern becomes addresses.

Wildcard domain rules resolve through the DNS cache and Resolve-DnsName. The elevated worker can refresh that set about every five minutes. The block is on the address, not on the name inside an encrypted session.

Charts that keep moving.

System monitor samples CPU, memory, network, and disk every few seconds. Per-core load and the busiest processes stay on the same page.

Policies are a catalog.

A policy can name process patterns, services, paths, addresses, and ports. Nothing in the background turns that file into firewall rules. A block still happens only when you apply it.

Events stay structured.

Firewall log rows show direction, application, and the path from source to destination. Open the row. Start a block from the application path when it is known.
