Technical detail

The operating contract.

Requirements and behavior are stated plainly. Where Windows, drivers, permissions, or another security product can change the result, that dependency is part of the specification.

Platform & runtime

Target
Windows 11 is the documented and validated platform.
Python
Python 3.11 for the local API. The standard launcher requests py -3.11 when the Python launcher is available.
Node.js
Node.js and npm are required by the standard Vite launcher and for dashboard builds. A prebuilt dashboard can be served by the API.
Observation
No administrator rights are required for basic use, but Windows may hide protected process, socket, signature, or event details.
Mutation
Firewall changes, audit-policy changes, and optional capture require administrator approval through UAC.
Network
API on 127.0.0.1:8765. Development dashboard on 127.0.0.1:5173.

Application stack

Frontend
React 18, TypeScript, Fluent UI v9, TanStack Query, and Vite.
Backend
FastAPI, Uvicorn, Pydantic, and psutil.
Persistence
SQLite activity, managed-rule history, and wildcard domain patterns.
Windows data
NetSecurity cmdlets, Windows event logs, DNS client data, CIM, performance counters, and optional nvidia-smi.
Data refresh
HTTP polling through TanStack Query. No WebSocket or push stream is required.
Chart history
Recent samples are held in browser memory and reset when the view unmounts or reloads.

Firewall behavior

Action
The managed workflow creates block rules. It does not create allow rules.
Direction
Outbound is the default. Inbound can also be selected in the block dialog.
Targets
Application paths, Windows services, and remote IPv4 or IPv6 addresses. Backend validation also supports port-scoped rules.
Batch creation
Up to 50 targets in one request, with one elevated process and per-target results.
Identity
Names use the FGF- prefix and the Firewall Guard Fluent group.
Verification
Created rules are queried with Get-NetFirewallRule. Verification does not prove that an existing session has closed.
Removal
Backend removal is restricted to FGF--prefixed names. Treat removal as a live administrative operation.

Telemetry & evidence

System
CPU, memory, network, and disk metrics refresh about every 3 seconds in the monitor.
GPU
GPU views refresh about every 4 seconds. Availability depends on drivers and Windows counters.
Traffic
Current sockets and recent event data refresh through near-live polling, not a continuous packet stream.
DNS
Hostnames come from the Windows DNS cache. Wildcard candidates also use Resolve-DnsName.
Domain refresh
An optional elevated broker can refresh enabled patterns about every 5 minutes when live mode and broker conditions are met.
Events
Firewall/WFP event visibility depends on audit policy, log permissions, and the fields Windows supplies.
Policies
policies.json is a read-only catalog. No automatic background policy enforcement engine is active.

Confirm the active dry-run mode before making changes.

Configuration can differ between development machines. Dry-run block creation records intent without creating rules. Rule removal is a separate live administrative action and must be reviewed deliberately.

Evidence boundaries

What the console does not claim.

A trustworthy operational tool distinguishes what Windows reports from what it cannot prove.

01 / CONTENT

No TLS inspection

Socket, DNS, and event metadata do not reveal encrypted content, URLs, payloads, or the purpose of a transfer.

02 / SESSIONS

Blocks are not session termination

A new firewall rule may leave an already-established connection open. Verify the resulting state rather than assuming immediate disconnection.

03 / AUTHORITY

Other controls still apply

Group Policy, VPN clients, and other security products can affect the same path and the effective Windows Firewall result.

Development status

Review before reliance.

Firewall Guard is a local development project, not a signed commercial security product. Review the source, replace the development token, and validate administrative workflows on a test machine.
