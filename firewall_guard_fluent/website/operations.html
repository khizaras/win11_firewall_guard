Quick start

One launcher. Two local services.

The standard workflow starts the FastAPI backend and Vite dashboard in minimized console windows, waits for their listeners, and opens the browser automatically.

01

Prepare Windows.

Use Windows 11 with Python 3.11 and Node.js 20 or newer available. The launcher creates backend\.venv, installs Python dependencies when their hash changes, and installs frontend packages when node_modules is absent.

Python 3.11 · Node.js 20+First run may require internet access for packages
02

Double-click the launcher.

Open the project root and run Start Firewall Guard.bat. It is a pure batch launcher. Keep the FGF Backend and FGF Dashboard console windows open while you use the app.

Start Firewall Guard.batProject root · Pure batch startup
03

Inspect the local state.

The browser opens the dashboard after the local listener appears. Confirm the API badge, firewall profiles, and active dry-run mode before attempting a mutation.

http://127.0.0.1:5173

Safety modes

Know the mode before the mutation.

The console exposes dry-run and live modes. Configuration can differ between development machines, so verify the active state rather than assuming a default.

Dry-run block creation.

Records the intended block request without creating Windows Firewall rules. Use it to review targets and the batch workflow before enabling live changes.

Rule removal is a separate live administrative operation. Do not rely on dry-run as a removal safeguard.

Live administrative change.

Selected firewall mutations invoke elevated Windows PowerShell. Review the UAC prompt and inspect per-target results rather than assuming success.

A new block rule may not close an already-established session. Other firewall and security controls still apply.

Replace the development token and keep the API on loopback.

Update backend/config/settings.json and set the same value as VITE_API_TOKEN in frontend/.env. Do not expose port 8765 to a LAN or the internet.

Full boundaries

Optional same-origin mode

Build once. Serve through the API.

When frontend/dist exists, FastAPI can serve the built dashboard on port 8765. Start Uvicorn directly instead of the standard Vite launcher.

01

Build the dashboard.

Run the production build from the frontend directory. This compiles TypeScript and writes the static dashboard to frontend/dist.

npm run build
02

Start only the backend.

From the backend directory, start Uvicorn with the project virtual environment. Open http://127.0.0.1:8765 after the API is ready.

.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765

Recovery guide

When the evidence is missing.

Start with the local service, the Windows permission, or the driver that supplies the data.

The dashboard is empty or cannot reach the API

Confirm that the FGF Backend window is still open and that 127.0.0.1:8765 is listening. Review fgf-backend.log in the project root. If Vite moved to another port because 5173 was occupied, use the address shown in frontend/fgf-vite.log; cross-origin API access may require correcting the port configuration.

The launcher says a port is already in use

Identify the process that owns ports 8765 or 5173 before stopping anything. The stop batch file terminates the process trees listening on those ports, so confirm they belong to Firewall Guard rather than another development tool.

Firewall events are empty

Recent WFP events require the appropriate Windows packet-audit policy and permission to read the event log. An empty result can indicate unavailable evidence, not necessarily an absence of traffic. Existing connections also may not generate a new event.

GPU or per-process counters are unavailable

GPU support depends on the adapter, driver, nvidia-smi when present, and Windows performance counters. Protected processes can hide disk or ownership data. The console should show unavailable evidence rather than inventing a value.

A verified block did not close the current session

Windows Firewall rule creation and established-session teardown are different outcomes. Recheck current sockets, live rules, Group Policy, VPN behavior, and other endpoint-security controls before drawing a conclusion.

Stop the standard launcher

Close the FGF Backend and FGF Dashboard console windows, or run Stop Firewall Guard.bat after confirming that ports 8765 and 5173 belong to this app. The standard stop script does not manage every optional elevated worker or capture state.
